# Diff Preview — Design Spec

**Date:** 2026-05-05
**Branch:** feat/diff-preview
**Status:** Approved

## Overview

Store the raw unified diff for each review in the database and surface it inside the dashboard's ReviewDetail page as an inline diff viewer, with findings highlighted at their exact line positions.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Layout | Three-panel (findings / diff / detail) | Most information-dense without tabs; all context visible at once |
| Diff scope in middle panel | Full file diff for selected finding's file | Natural scope — broader than a hunk snippet, narrower than full PR diff |
| Diff storage | Raw unified diff TEXT in `reviews` table, stored as-is | Simple, no data loss; most PR diffs are well under 100KB |
| Diff renderer | `diff2html` (npm) | Production-grade, used by GitLab/Gitea, handles all unified diff edge cases, ships dark theme CSS |

Add one nullable column to the `Review` SQLAlchemy model:

raw_diff: Mapped[str | None] = mapped_column(Text, nullable=True)

Nullable so all existing rows remain valid.

In `_async_run_review`, after fetching the diff and before running the engine, save it to the review row:

## Section 2 — Frontend Diff Parsing & Rendering

### Dependency

```bash
npm install diff2html
# in packages/dashboard
```

### Utility: `src/lib/parseDiff.ts`

Two exported functions:

**`extractFileDiff(rawDiff: string, filePath: string): string`**

Splits the raw unified diff on `diff --git` markers and returns the section whose `+++ b/<path>` line matches `filePath`. Returns an empty string if no match found.

```typescript
export function extractFileDiff(rawDiff: string, filePath: string): string {
  const sections = rawDiff.split(/(?=^diff --git )/m);
  return sections.find(s => s.includes(`+++ b/${filePath}`)) ?? '';
}
```

**`findingLineRange(finding: Finding): Set<number>`**

Returns the set of new-file line numbers `[line_start, line_end]` inclusive, used to identify which rendered rows to highlight.

```typescript
export function findingLineRange(finding: Finding): Set<number> {
  const lines = new Set<number>();
  for (let i = finding.line_start; i <= finding.line_end; i++) lines.add(i);
  return lines;
}
```

### Component: `src/components/DiffPanel.tsx`

Props:
```typescript
interface DiffPanelProps {
  rawDiff: string | null;
  finding: Finding | null;
}
```

Behaviour:
1. If `rawDiff` is null, renders a `"No diff available"` placeholder (covers reviews created before this feature).
2. When `finding` changes, calls `extractFileDiff(rawDiff, finding.file_path)` to get the file section.
3. Passes the file section to `diff2html` in `line-by-line` output format with `drawFileList: false`.
4. Renders the HTML via `dangerouslySetInnerHTML` into a ref'd container div. (Safe: the HTML is generated by `diff2html` from diff text fetched from our own API — no user-controlled HTML is ever injected.)
5. In a `useEffect` (after render), queries the rendered rows for `<td>` line number cells in `[finding.line_start, finding.line_end]`:
   - Adds a highlight CSS class to the matching `<tr>` rows.
   - Appends a severity badge element to the first matched row.
6. Calls `scrollIntoView({ behavior: 'smooth', block: 'center' })` on the first highlighted row.

### CSS (`src/index.css`)

A small block of CSS custom property overrides targets `diff2html`'s CSS variables to match the `#0d1117` dark background, `#21262d` borders, and existing severity colours. No conflicts with Tailwind utility classes.

## Section 3 — Three-Panel Layout

### `ReviewDetail` layout change (`src/components/ReviewDetail.tsx`)

The existing two-panel `flex` container becomes three panels:

| Panel | Width (lg) | Width (mobile) | Content |
|---|---|---|---|
| Left | `lg:w-1/4` | full width | Findings list (current code, no changes) |
| Middle | `lg:w-1/2` | full width | New `DiffPanel` component |
| Right | `lg:w-1/4` | full width | `FindingDetail` card (current code, no changes) |

Mobile stacking order: findings → diff → detail (top to bottom).

`DiffPanel` receives:
- `rawDiff={data.raw_diff}` from the existing `useQuery` result
- `finding={selectedFinding}` from the existing `selectedFinding` state

No other changes to `ReviewDetail`: header, score badge, retry button, back navigation, and auto-select-first-finding behaviour are all unchanged.

## Out of Scope

- Side-by-side diff format (line-by-line is sufficient for the narrow panel)
- Diff size cap / truncation (deferred; most real PR diffs are well under 100KB)
- Syntax highlighting inside diff lines (diff2html handles colouring via its CSS; language-level syntax highlighting is a future enhancement)
- Showing diffs for reviews triggered via CLI `--file` (those have no GitHub PR diff URL; `raw_diff` will be null)
